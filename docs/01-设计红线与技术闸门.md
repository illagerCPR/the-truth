## 0. 四条设计红线（复述）

来自 `00-世界观创意方案.md` 第 10 节，任何技术方案与它们冲突时以红线为准：

1. **进不去**：入口门槛位于 AE2 后期（空间 IO + 成对纠缠奇点），不提供绕过路径。
2. **活不下去**：维度内物质不稳定，必须建立确定性覆盖才能长期作业。
3. **挖不动**：地层不由普通工具开采，必须经 ME 手段"读"进网络——自动化是正解。
4. **带得走**：维度产物必须反向增强主世界的 AE2 能力。

---

## 1. 红线 1 · 进不去（入口与回程）

### 1.1 设计意图

入口不是一扇门，而是一次"存储与传输"。玩家在主世界搭建「确界锚点」多方块结构，以**成对量子纠缠奇点**为钥匙，借由空间 IO 语义被投递进确界。

### 1.2 技术能力核对

| 能力 | 用途 | 结论 |
| --- | --- | --- |
| 玩家跨维度传送 | 进入与返回 | ✅ `DimensionTransition` + `ServerPlayer#teleportTo` |
| 过渡界面定制 | "被存储"的表现 | ✅ NeoForge `RegisterDimensionTransitionScreenEvent` |
| 结构成型检测 | 确界锚点 | ✅ 自研（原版无此依赖） |
| 钥匙物品校验 | 成对纠缠奇点 | ✅ 普通物品处理，无需前置 API |
| 门槛保证 | 必须打通 AE2 后期 | ✅ 自研：校验消耗空间元件 / 需要空间 IO 端口 |

### 1.3 结论与实现方案

**闸门通过。** 1.21.1 已有完整的跨维度传送 API（已用本机反编译工件 `javap` 核实签名）：

- `net.minecraft.world.level.portal.DimensionTransition`（record）：`newLevel()`、`pos()`、`speed()`、`yRot()`、`xRot()`、`postDimensionTransition()`；常量 `DO_NOTHING` / `PLAY_PORTAL_SOUND` / `PLACE_PORTAL_TICKET`。
- `Entity#changeDimension(DimensionTransition)` → 返回 `Entity`。
- `ServerPlayer#teleportTo(ServerLevel, double, double, double, float, float)`。
- NeoForge 追加 `RegisterDimensionTransitionScreenEvent`，可定制过场界面——**正好用来做"被存储并传输"的表现**。

参考实现：AE2 自己的 `appeng/spatial/SpatialStorageHelper.java#teleportEntity` 就是这么写的，可直接照抄写法。

**退路**：若前置的空间 IO 不提供可编程触发点，入口改为自研"投递装置"多方块，但仍要求消耗空间元件，以保住"门槛在 AE2 后期"这一红线。

## 2. 红线 2 · 活不下去（确定性覆盖）

### 2.1 设计意图

物品在确界内累积"不确定度"，只有处于**确定性覆盖**内才稳定。覆盖 = 玩家能访问到某个 ME 网络（复用 AE2 无线覆盖语义），或处于确界锚点 / 脐带锚点的作用范围。

### 2.2 技术能力核对

| 能力 | 用途 | 结论 |
| --- | --- | --- |
| 无线接入点查询 | 覆盖判定核心 | ✅ `appeng.api.implementations.blockentities.IWirelessAccessPoint` |
| 网络查询 | 判断网络是否在线 | ✅ `appeng.api.networking.GridHelper` / `IGrid` / `IGridNode` |
| 玩家级持久数据 | 不确定度累积值 | ✅ NeoForge Data Attachment（`AEAttachmentTypes` 同款做法） |
| 物品栏逐 tick 检查 | 累积与损耗 | ✅ 玩家 tick 事件 |
| 预警表现 | 噪点、闪烁、音效前摇 | ✅ 自研（客户端） |

### 2.3 结论与实现方案

**闸门通过（高置信）。** 公开 API `IWirelessAccessPoint extends IActionHost` 提供：

```java
DimensionalBlockPos getLocation();
double getRange();
boolean isActive();
IGrid getGrid();
```

覆盖判定的实现路径：在玩家所在维度扫描附近的 `IWirelessAccessPoint` 方块实体，`isActive()` 为真且玩家与 `getLocation()` 的距离 ≤ `getRange()` 即视为"处于确定性覆盖内"。

**首版退化策略（M3 修正版）**：AE2 19.2.17 的 API 包内**没有**终端判别接口——`appeng.api.implementations.items` 下不存在 `IWirelessTerminalItem`（2026-09-26 对 jar 核实；无线终端类 `appeng.items.tools.powered.WirelessTerminalItem` 实现的 `IMenuItem` / `IUpgradeableItem` 均不承载"无线"语义，用它判别需要 import 内部类）。因此首版覆盖判定收敛为：**玩家处于活跃 `IWirelessAccessPoint` 的作用范围内即视为被覆盖**（`isActive()` 且与 `getLocation()` 距离 ≤ `getRange()`）。这与 4.1 的定义"玩家能访问到某个 ME 网络即视为被覆盖"更一致：网络覆盖玩家 = 玩家被记录，无需手持终端佐证。实现走"接入点侧注册反查"不可行（AE2 的接入点 BE 无公开注册表），改为按玩家所在 chunk 为中心扫描周边 chunk 的 BlockEntity 过滤 `IWirelessAccessPoint`（初值扫描半径 4 chunk = 覆盖距离 ≤64 格的接入点，每 20 tick 一次）。

## 3. 红线 3 · 挖不动（开采必须经由 ME）

### 3.1 设计意图

确界地层不是"物质"，而是"被描述的物质"。普通工具无法开采，必须用 AE2 的破坏面板 / 导入手段把它"读"进网络。

### 3.2 AE2 破坏面板的真实开采路径（已读源码）

`appeng/parts/automation/AnnihilationPlanePart.java` → `appeng/parts/automation/ItemPickupStrategy.java`：

1. `canHandleBlock(level, pos, state)` 要求 **`hardness >= 0f`** 且 `level.mayInteract(fakePlayer, pos)`。
2. 掉落：`Block.getDrops(state, level, pos, blockEntity, fakePlayer, harvestToolItem)`。
3. 随后 `level.destroyBlock(pos, false)`。**掉落直接进网络，不落地**。
4. 工具是 `createHarvestTool(state)` 造的**原版钻石工具**（按 `MINEABLE_WITH_*` 标签选镐/斧/锹/锄）+ 面板上的附魔。

### 3.3 结论与实现方案

**闸门通过（高置信），且不需要 AE2 API、不需要 mixin。**

两个关键结论：

- ✅ **不能用 `hardness = -1`**：`canHandleBlock` 会直接拒绝，连破坏面板都挖不了，会同时废掉正解路径。
- ✅ **判别依据必须是实体，不能是工具**：破坏面板传的是原版钻石工具，无法据此识别 AE2；但 loot context 里的 `THIS_ENTITY` 是 AE2 的假玩家（`Platform.getFakePlayer`）。

**实现方案**：确界地层方块使用正常硬度，但掉落只在"**非真实玩家**"开采时产生（掉落表自定义条件，或覆写 `Block#getDrops` 检查 `LootContextParams.THIS_ENTITY` 是否为 `FakePlayer`）。真实玩家开采零掉落 + 明确反馈（粒子/提示）。

副作用是好的：这实际上把"必须自动化"写成了机制，比"绑定某个特定模组的工具"更稳、更符合"必须经由 ME"的语义。

## 4. 红线 4 · 带得走（确界存储层）

### 4.1 设计意图

确界元件：容量极大，但网络不可达时内容进入「未定形」状态（不可取出、不丢失、可恢复）。

### 4.2 技术能力核对

| 能力 | 用途 | 结论 |
| --- | --- | --- |
| 存储元件接口 | 被 ME 驱动器识别 | ✅ `appeng.api.storage.cells.StorageCell` + `IBasicCellItem` |
| 状态显示 | 未定形提示 | ✅ `CellState` 枚举 / 自定义 tooltip |
| 元件存档 | 未定形状态持久化 | ✅ `persist()` + `ISaveProvider` |
| 网络存储对接 | 正常读写 | ✅ `MEStorage` / `IStorageProvider` / `KeyCounter` |
| 轴线类接口 | 工作台、升级 | ✅ `ICellWorkbenchItem` / `appeng.api.upgrades.*` |

### 4.3 结论与实现方案

**闸门通过（高置信）。** 公开 API 足以实现一个完整的存储元件：

```java
public interface StorageCell extends MEStorage {
    CellState getStatus();
    double getIdleDrain();
    default boolean canFitInsideCell();
    void persist();
}

public interface IBasicCellItem extends ICellWorkbenchItem {
    AEKeyType getKeyType();
    int getBytes(ItemStack cellItem);
    int getBytesPerType(ItemStack cellItem);
    int getTotalTypes(ItemStack cellItem);
    double getIdleDrain();
    // ...
}
```

配套还有 `CellState`（ABSENT / EMPTY / NOT_EMPTY / TYPES_FULL / FULL）、`ICellHandler`、`ISaveProvider`、`IStorageProvider`、`MEStorage`、`KeyCounter`。

「未定形」的实现：元件在脱离网络时把内容标记为未定形（`MEStorage` 对外报告不可提取，`getStatus()` 给出对应状态，`persist()` 存档），重新接入网络时恢复。**不需要任何内部类。**

依赖接入方式（M0 使用）：

```gradle
repositories { mavenCentral() }

dependencies {
    // 完整模组 jar（dev 环境需要真实加载 AE2）；GuideME 由 POM 传递带入
```

**纪律**：我们只允许 import `appeng.api.**`。若某处必须触碰内部类，必须在 `02-开发计划.md` 中登记为风险并说明理由。

### 5.2 维度注册（1.21.1）

- `data/thetruth/dimension_type/certus.json`：字段集合参照 vanilla `the_end`——`ambient_light`、`bed_works`、`coordinate_scale`、`effects`、`fixed_time`、`has_ceiling`、`has_raids`、`has_skylight`、`height`、`infiniburn`、`logical_height`、`min_y`、`monster_spawn_block_light_limit`、`monster_spawn_light_level`、`natural`、`piglin_safe`、`respawn_anchor_works`、`ultrawarm`。
- `data/thetruth/dimension/certus.json` = **LevelStem**：

```json
{
  "type": "thetruth:certus",
  "generator": {
    "type": "minecraft:noise",
    "biome_source": { "type": "..." },
    "settings": "thetruth:certus"
  }
}
```

- 服务端取维度：`server.getLevel(ResourceKey.create(Registries.DIMENSION, ResourceLocation.fromNamespaceAndPath("thetruth", "certus")))`。
- `effects` 指向客户端 `DimensionSpecialEffects`，需自行注册以实现"观测白光"。

### 5.3 区块生成与生物群系

- **自定义生成器**：注册 `Codec<? extends ChunkGenerator>` 到 `Registries.CHUNK_GENERATOR`，JSON 里 `generator.type` 指向它。
- **分期策略（降风险）**：
  - M1：先用 `minecraft:noise` + `data/thetruth/worldgen/noise_settings/certus.json` 出可玩地形，打通"能进去、能看见、能站稳"。
  - M2：再替换为自定义 ChunkGenerator，实现"中央残片 + 碎片带 + 整齐虚空缺口"的签名视觉。
- 生物群系：`data/thetruth/worldgen/biome/*.json`。

### 5.4 本机构建缓存现状

- ✅ 已缓存：MC 1.21.1 client/server 原始 jar、NeoForge **21.1.119** 的 NeoForm 中间产物、Gradle 8.8 发行版。
- ⚠️ 需下载：NeoForge **21.1.248**、AE2 19.2.17 与 GuideME、Parchment 映射。
- ⇒ **M0 首次构建需要关闭 `~/test/Steamcommunity_302/` 反代**（自签证书会让 Java 下载失败），完成后再开启。
