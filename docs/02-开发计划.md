## 1. 目标与范围

### 1.1 目标

交付一个 Minecraft 1.21.1 / NeoForge 模组 **The Truth**，前置 Applied Energistics 2，包含一个与前置强相关的维度「确界 / Certus」，落实 `00-世界观创意方案.md` 中的四条设计红线。

### 1.2 定位

AE2 终局扩展：1 个维度（三层结构）+ 1 个 Boss + 1 条新机器链（确界存储层）+ 不可逆的终局世界状态标记。

### 1.3 首版不做

见 `00-世界观创意方案.md` 第 11 节（范围收敛）：不做其他模组兼容、不做独立能量体系、不做完整维度科技树、不做全维度叠加态模拟、不做双端分离内容、不做村民交易体系。

## 3. 里程碑与批次拆解

每个批次完成后立即提交并推送，等待 CI 变绿再进入下一批次（见第 6 节）。

### M0 · 工程骨架与 CI

- **交付**：Gradle 工程（`build.gradle`、`gradle.properties`、`settings.gradle`、wrapper）、主类与模组元数据（`META-INF/neoforge.mods.toml`、`pack.mcmeta`）、AE2 依赖接入、GameTest 测试基建（`gameTestServer` 运行入口 + 冒烟测试；测试类暂置主源集，是否随发布剥离在 M3 前评估）、`.github/workflows/build.yml`。
- **依赖接入**（已核对，见 `01` 文档 5.1）：

```gradle
plugins { id 'net.neoforged.moddev' version '2.0.147' }

neoForge { version = '21.1.248' }

repositories { mavenCentral() }

dependencies {
    implementation "org.appliedenergistics:appliedenergistics2:19.2.17"
    compileOnly "org.appliedenergistics:appliedenergistics2:19.2.17:api"
}
```

- **纪律**：只允许 import `appeng.api.**`；若必须触碰前置内部类，需登记为风险并说明理由。
- **验收**：`./gradlew build` 产出 jar；`runClient` 中模组列表可见 The Truth **且 AE2 与 GuideME 均已加载**；CI 首次变绿。
- **验收结果（2026-09-26）**：✅ `build` 成功（13m10s，含 NeoForm 全流水线）；✅ `runGameTestServer` 冒烟测试 `All 1 required tests passed`；✅ dev 启动的 Mod List 证实 `thetruth 0.1.0` + `ae2 19.2.17` + `guideme 21.1.1` 同载（与 runClient 同一加载路径，GUI 视觉确认留给用户日常验证）；CI 待绿。
- **过程收获**：GameTest 模板必须二进制 `.nbt`（数据包路线不读 `.snbt`），生成器入库 `tools/make_empty_structure.py`；大文件下载卡死的根因是 WSL2 MTU 黑洞（详见 `AGENTS.md` 环境陷阱）。
- **前置动作**：首次构建需下载 NeoForge 21.1.248、AE2、GuideME 与 Parchment 映射 —— 执行前提醒用户**关闭** `~/test/Steamcommunity_302/` 反代（自签证书会导致 Java 下载失败），完成后提醒重新开启。

### M1 · 维度骨架

- **交付**：维度类型与维度 JSON、区块生成方案落地、调试用传送入口、确界自有基础方块注册。
- **验收**：能进入确界并看到地形；退出重进维度状态稳定；无生成期异常。
- **闸门**：ChunkGenerator 方案在 `01` 文档中定稿（自写生成器 vs 自定义 noise settings）。
- **交付清单（2026-09-26）**：
  - 维度 JSON：`data/thetruth/dimension_type/certus.json`（min_y=-64 / height=320，effects 暂用 overworld，M2 换观测周期）、`data/thetruth/dimension/certus.json`（`minecraft:noise` 生成器 + fixed biome source）。
  - 地形：`worldgen/noise_settings/certus.json`——`final = rise(-32→16) × (mask×(2+三维噪声) + 顶带衰减(120→224: 0→-3))`，水平掩码 `mask = clamp(flat_cache(islands)×5 + 0.15, 0, 1)`。掩码≈0 的整列虚空（笔直竖直缺口的雏形）、不同掩码列的顶面高度参差（漂浮岛群）、底面 y=-32 截断。引用自定义噪声 `certus_terrain`（细节）与 `certus_islands`（大尺度破碎）。M2 将替换为三层精确地形与网格缺口。
  - 方块：`certus_stone`（确界石）注册 + BlockItem + 自建创造模式标签 `thetruth:main` + 模型/贴图（程序化占位，`tools/make_placeholder_textures.py`）+ 语言文件（en_us / zh_cn）。
  - 调试命令：`/thetruthdebug certus` 与 `/thetruthdebug overworld`（OP 权限 2，**明确不是玩法入口**，红线 1 的正式入口在 M4）。
  - GameTest：`certusWorldgenRegistriesLoaded`（dimension_type/biome/noise_settings 解析与字段断言）、`certusDensityProfile`（密度树算术壳采样：上下虚空、中带为正）、`certusIslandNoiseVaries`（固定种子直接采样 `NormalNoise` 证明掩码噪声非退化——真实生成中缺口存在的前提），加 M0 冒烟共 4 项全过。
- **验收结果（2026-09-26）**：✅ `build` 成功；✅ `runGameTestServer` `All 4 required tests passed`，日志零异常。人工 runClient 首验发现两缺陷并当场修复：①传送落点未强制 FULL 区块且 y=128 兜底落在实心板内 → 改为强制 FULL 后自上而下扫「实心+上两格空气」站位；②初版密度只在 y 向衰减、从不穿零，顶面呈 y=240 水平大平板 → 重构为上表穿零 + 水平掩码破碎（见上）。二验又发现三缺陷并修复：③传送点恰为掩码空列导致坠落 → 落点改为自原点环形搜索（SURFACE 状态预筛空列，FULL 生成后扫站位）；④确界下方出现岩浆海 → 根因是 `NoiseBasedChunkGenerator` 的**全局流体 picker 与 `aquifers_enabled` 无关**，`y < min(-54, sea_level)` 的空腔无条件填岩浆，`sea_level` 从 0 改为 -64（=维度 minY）后世界内不再有岩浆层；⑤岛柱落差 75+ 格过陡 → 顶带收敛为 96→176（顶面约 y110–150）、掩码增益锐化 ×8+0.05（悬崖更笔直）。
- **过程收获（1.21.1 硬事实，后续批次直接用）**：
  - **vanilla `GameTestServer.create` 硬编码 `WorldPresets.FLAT` 建世界并丢弃 datapack 的 LevelStem（`dimension/*.json`）**——GameTest 环境永远无法实例化 datapack 维度。机制测试改为：worldgen registry 加载断言 + `NoiseRouter.finalDensity().compute(SinglePointContext)` 纯函数采样。**采样方法论边界：`interpolated`/`flat_cache` 节点在 NoiseChunk 之外退化为 0**（单点采样只能验证密度树的算术壳，绑定节点的真实行为靠 runClient 人工验收），故另设 `certusIslandNoiseVaries` 用固定种子直接采样 `NormalNoise` 验证掩码噪声有效。"进维度看地形"属观感验收，走 runClient 人工确认。
  - `noise_settings` JSON 的 `spawn_target` 与 `surface_rule` 是**必填键**（缺了直接 registry 加载失败）；`minecraft:noise` 密度函数需要显式 `xz_scale` / `y_scale`。
  - mappings 修正：`ChunkStatus` 在 `net.minecraft.world.level.chunk.status`；`Level` 取最低 y 用 `getMinBuildHeight()`（`minY()` 是 `DimensionType` 的）；NeoForge 事件订阅注解是独立类 `net.neoforged.fml.common.EventBusSubscriber`（`Mod.EventBusSubscriber` 不存在），`bus` 属性已废弃（默认 GAME）。
  - 1.21.1 掉落表目录已是单数 `loot_table/`，tag 目录是单数 `tags/block/`。

## 4. 验证策略

原则：**把机制正确性尽量塞进自动化，只在游戏内验证观感与手感。**

| 手段 | 覆盖对象 | 说明 |
| --- | --- | --- |
| `./gradlew build` | 编译、数据生成、资源完整性 | 每批次必跑，CI 门禁 |
| GameTest（无头逻辑测试） | 覆盖判定、不确定度曲线、元件未定形状态机、多方块结构成型 | ✅ 已决策引入；M0 建立基建 |
| 数据生成一致性 | 配方、标签、语言键 | 防止手写 JSON 漂移 |
| 游戏内人工验证 | 维度观感、观测周期氛围、Boss 手感、入口仪式表现 | 无法自动化，逐批次人工确认 |

## 5. 风险登记表

| 风险 | 影响 | 缓解 / Fallback |
| --- | --- | --- |
| AE2 破坏面板无公开挂钩点（红线 3） | 高 | 退路一：NeoForge 侧用 `PlayerEvent.BreakSpeed` + 自定义工具判定；退路二：普通工具可挖但掉落「未定形质」，仍需确界固化器加工（保住"必须经由 ME"的语义） |
| AE2 无无线覆盖查询 API（红线 2） | 中 | 自建覆盖判定：确界锚点场 + 自行查询玩家无线终端绑定与接入点距离 |
| 自定义 ChunkGenerator 工期 | 高 | 先用 `NoiseBasedChunkGenerator` + 自定义 noise settings 出可玩地形，碎片岛用特征/结构实现；稳定后再迭代为自写生成器 |
| 跨维度强加载的性能开销 | 中 | 限制脐带锚点数量；无玩家在线时不维持 |
| 不稳定机制劝退玩家 | 中 | 渐进曲线 + 永不静默删除 + 提供服务器可配开关 |
| AE2 后续版本破坏 API | 中 | 钉死 19.2.17；CI 中固定版本，升级作为独立批次评估 |
| 机制误伤创造模式或其他维度 | 低 | 不确定度只在确界维度内生效 |

（技术闸门已全部核对通过，结论与退路见 `01-设计红线与技术闸门.md` 第 6 节；编码阶段仍需实测的项见该文档第 7 节。）

## 6. 交付与发布纪律

- **批次即推送**：每完成一个批次（实现 + 验证 + 提交）立即 `git push origin main`，不积压本地提交。
- **CI 门禁**：推送后用 `gh run watch <runId> --repo illagerCPR/the-truth --exit-status` 等 CI 变绿，再收尾汇报。
- **版本号单一来源**：版本号只写在 `gradle.properties` 一处；发布 checklist 必须包含"递增版本号"，并与 GitHub Release 在同一批次提交内完成。
- **发布前核对**：Release 前核对版本常量数值与目标 tag 一致，避免"界面一直显示旧版本"一类事故。
