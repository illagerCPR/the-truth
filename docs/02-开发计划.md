## 1. 目标与范围

### 1.1 目标

交付一个 Minecraft 1.21.1 / NeoForge 模组 **The Truth**，前置 Applied Energistics 2，包含一个与前置强相关的维度「确界 / Certus」，落实 `00-世界观创意方案.md` 中的四条设计红线。

### 1.2 定位

AE2 终局扩展：1 个维度（三层结构）+ 1 个 Boss + 1 条新机器链（确界存储层）+ 不可逆的终局世界状态标记。

### 1.3 首版不做

见 `00-世界观创意方案.md` 第 11 节（范围收敛）：不做其他模组兼容、不做独立能量体系、不做完整维度科技树、不做全维度叠加态模拟、不做双端分离内容、不做村民交易体系。

## 3. 里程碑与批次拆解

每个批次完成后立即提交并推送，等待 CI 变绿再进入下一批次（见第 6 节）。

### M0 · 工程骨架与 CI

- **交付**：Gradle 工程（`build.gradle`、`gradle.properties`、`settings.gradle`、wrapper）、主类与模组元数据（`META-INF/neoforge.mods.toml`、`pack.mcmeta`）、AE2 依赖接入、GameTest 测试基建（`gameTestServer` 运行入口 + 冒烟测试；测试类暂置主源集，是否随发布剥离在 M3 前评估）、`.github/workflows/build.yml`。
- **依赖接入**（已核对，见 `01` 文档 5.1）：

```gradle
plugins { id 'net.neoforged.moddev' version '2.0.147' }

neoForge { version = '21.1.248' }

repositories { mavenCentral() }

dependencies {
    implementation "org.appliedenergistics:appliedenergistics2:19.2.17"
    compileOnly "org.appliedenergistics:appliedenergistics2:19.2.17:api"
}
```

- **纪律**：只允许 import `appeng.api.**`；若必须触碰前置内部类，需登记为风险并说明理由。
- **验收**：`./gradlew build` 产出 jar；`runClient` 中模组列表可见 The Truth **且 AE2 与 GuideME 均已加载**；CI 首次变绿。
- **验收结果（2026-09-26）**：✅ `build` 成功（13m10s，含 NeoForm 全流水线）；✅ `runGameTestServer` 冒烟测试 `All 1 required tests passed`；✅ dev 启动的 Mod List 证实 `thetruth 0.1.0` + `ae2 19.2.17` + `guideme 21.1.1` 同载（与 runClient 同一加载路径，GUI 视觉确认留给用户日常验证）；CI 待绿。
- **过程收获**：GameTest 模板必须二进制 `.nbt`（数据包路线不读 `.snbt`），生成器入库 `tools/make_empty_structure.py`；大文件下载卡死的根因是 WSL2 MTU 黑洞（详见 `AGENTS.md` 环境陷阱）。
- **前置动作**：首次构建需下载 NeoForge 21.1.248、AE2、GuideME 与 Parchment 映射 —— 执行前提醒用户**关闭** `~/test/Steamcommunity_302/` 反代（自签证书会导致 Java 下载失败），完成后提醒重新开启。

### M1 · 维度骨架

- **交付**：维度类型与维度 JSON、区块生成方案落地、调试用传送入口、确界自有基础方块注册。
- **验收**：能进入确界并看到地形；退出重进维度状态稳定；无生成期异常。
- **闸门**：ChunkGenerator 方案在 `01` 文档中定稿（自写生成器 vs 自定义 noise settings）。
- **交付清单（2026-09-26）**：
  - 维度 JSON：`data/thetruth/dimension_type/certus.json`（min_y=-64 / height=320，effects 暂用 overworld，M2 换观测周期）、`data/thetruth/dimension/certus.json`（`minecraft:noise` 生成器 + fixed biome source）。
  - 地形：`worldgen/noise_settings/certus.json`——`final = rise(-32→16) × (mask×(2+三维噪声) + 顶带衰减(120→224: 0→-3))`，水平掩码 `mask = clamp(flat_cache(islands)×5 + 0.15, 0, 1)`。掩码≈0 的整列虚空（笔直竖直缺口的雏形）、不同掩码列的顶面高度参差（漂浮岛群）、底面 y=-32 截断。引用自定义噪声 `certus_terrain`（细节）与 `certus_islands`（大尺度破碎）。M2 将替换为三层精确地形与网格缺口。
  - 方块：`certus_stone`（确界石）注册 + BlockItem + 自建创造模式标签 `thetruth:main` + 模型/贴图（程序化占位，`tools/make_placeholder_textures.py`）+ 语言文件（en_us / zh_cn）。
  - 调试命令：`/thetruthdebug certus` 与 `/thetruthdebug overworld`（OP 权限 2，**明确不是玩法入口**，红线 1 的正式入口在 M4）。
  - GameTest：`certusWorldgenRegistriesLoaded`（dimension_type/biome/noise_settings 解析与字段断言）、`certusDensityProfile`（密度树算术壳采样：上下虚空、中带为正）、`certusIslandNoiseVaries`（固定种子直接采样 `NormalNoise` 证明掩码噪声非退化——真实生成中缺口存在的前提），加 M0 冒烟共 4 项全过。
- **验收结果（2026-09-26）**：✅ `build` 成功；✅ `runGameTestServer` `All 4 required tests passed`，日志零异常。人工 runClient 首验发现两缺陷并当场修复：①传送落点未强制 FULL 区块且 y=128 兜底落在实心板内 → 改为强制 FULL 后自上而下扫「实心+上两格空气」站位；②初版密度只在 y 向衰减、从不穿零，顶面呈 y=240 水平大平板 → 重构为上表穿零 + 水平掩码破碎（见上）。二验又发现三缺陷并修复：③传送点恰为掩码空列导致坠落 → 落点改为自原点环形搜索（SURFACE 状态预筛空列，FULL 生成后扫站位）；④确界下方出现岩浆海 → 根因是 `NoiseBasedChunkGenerator` 的**全局流体 picker 与 `aquifers_enabled` 无关**，`y < min(-54, sea_level)` 的空腔无条件填岩浆，`sea_level` 从 0 改为 -64（=维度 minY）后世界内不再有岩浆层；⑤岛柱落差 75+ 格过陡 → 顶带收敛为 96→176（顶面约 y110–150）、掩码增益锐化 ×8+0.05（悬崖更笔直）。三验发现缺陷⑥并修复：⑥`/thetruthdebug certus` 报「找不到合适位置」→ 根因是 `MOTION_BLOCKING_NO_LEAVES` 属于 `FINAL_HEIGHTMAPS`，**从 CARVERS 状态才开始维护**，对 SURFACE 区块查询全部返回最低值 → 预筛全部误判空列；修复为预筛查 `WORLD_SURFACE_WG`（SURFACE 区块即有）并直接对 proto chunk 查询（`x & 15` 局部坐标），命中后再 FULL 生成做精细站位扫描。用户验收通过（观测感观以「地形参数冻结」收尾，M2 换三层精确地形）。
- **过程收获（1.21.1 硬事实，后续批次直接用）**：
  - **vanilla `GameTestServer.create` 硬编码 `WorldPresets.FLAT` 建世界并丢弃 datapack 的 LevelStem（`dimension/*.json`）**——GameTest 环境永远无法实例化 datapack 维度。机制测试改为：worldgen registry 加载断言 + `NoiseRouter.finalDensity().compute(SinglePointContext)` 纯函数采样。**采样方法论边界：`interpolated`/`flat_cache` 节点在 NoiseChunk 之外退化为 0**（单点采样只能验证密度树的算术壳，绑定节点的真实行为靠 runClient 人工验收），故另设 `certusIslandNoiseVaries` 用固定种子直接采样 `NormalNoise` 验证掩码噪声有效。"进维度看地形"属观感验收，走 runClient 人工确认。
  - `noise_settings` JSON 的 `spawn_target` 与 `surface_rule` 是**必填键**（缺了直接 registry 加载失败）；`minecraft:noise` 密度函数需要显式 `xz_scale` / `y_scale`。
  - mappings 修正：`ChunkStatus` 在 `net.minecraft.world.level.chunk.status`；`Level` 取最低 y 用 `getMinBuildHeight()`（`minY()` 是 `DimensionType` 的）；NeoForge 事件订阅注解是独立类 `net.neoforged.fml.common.EventBusSubscriber`（`Mod.EventBusSubscriber` 不存在），`bus` 属性已废弃（默认 GAME）。
  - 1.21.1 掉落表目录已是单数 `loot_table/`，tag 目录是单数 `tags/block/`。

### M2 · 地形与观测周期

- **交付**：残骸带 / 沉积层 / 未观测三层地形、整齐的虚空网格缺口、观测期与未观测期的状态机（光照、雾效、天空）、生物群系。
- **验收**：三层均可达；观测周期可见且切换平滑；"缺口"视觉签名成立（笔直边缘，不是自然洞穴）。
- **交付清单（2026-09-26）**：
  - **自写生成器 `CertusChunkGenerator`**（`worldgen/` 包，codec 注册到 `Registries.CHUNK_GENERATOR`）：替换 M1 的 `minecraft:noise` 生成器。理由：三层精确高度带与整齐网格缺口需要 `mod`/`floor` 类运算，原版密度函数没有对应节点；垂直分层 biome 也没有原版 biome source 支持（`02` 风险登记表预留的迭代路径）。`dimension/certus.json` 改为 `{"type": "thetruth:certus", "biome_source": {...fixed...}}`；M1 的 `noise_settings` 与 `noise` JSON 保留（噪声参数被 `RandomState#getOrCreateNoise` 继续复用，`noise_settings` 供 M1 密度测试回归）。
  - **地形形状 `CertusTerrainShape`**（纯函数，可单测）：网格缺口（cell 48 / 缺口宽 12，井字条带，观测台 48×48 方域豁免以保证 Boss 场地完整）+ 表层中央残片（|x|,|z|≤96，y 105–132）+ 表层漂浮岛（岛掩码沿用 M1 的 ×8+0.05 锐化，阈值 0.25，顶面 88–200，厚度 8–32）+ 中层沉积板（-16 到 48–72 起伏顶）+ 深层观测台（|x|,|z|≤24，y -48–-40，M6 Boss 场地雏形）。三层均可达：表层落点在残片顶（y≈133），中层沿缺口/边缘下潜，深层观测台位于 -40。
  - **垂直分层 biome**：`certus_debris`（≥80）/ `certus_sediment`（-16–79）/ `certus_unobserved`（<-16），由生成器 override `createBiomes` 直接按段填充（不再采样 biome source）。
  - **观测周期状态机 `ObservationCycle`**（纯函数）：周期 19200 tick（16 min）= 观测核心 11400 + 黄昏过渡 1300 + 未观测核心 5200 + 黎明过渡 1300（文档初值 10 min / 6 min 圆整到整数段）；`observationBlend` 输出观测强度 0..1（过渡段 smoothstep 单调）；`mapToSkyPhase` 把周期 tick 分段线性映射到原版天空相位 [0,24000)，段端点连续且周期回绕（19200→0）。服务端驱动 `ObservationCycleTicker`（`LevelTickEvent.Post`）：每 tick 用 `gameTime % 周期` 重写维度 `dayTime`，天空、天光亮度、怪物燃烧等原版系统自动跟随——无状态、可重入。
  - **客户端氛围 `CertusDimensionEffects`**：`dimension_type.effects` 换 `thetruth:certus`，经 `RegisterDimensionSpecialEffectsEvent`（client mod bus）注册；雾色在观测期冷白 (0.74,0.81,0.90) 与未观测期近黑 (0.012,0.016,0.024) 间按天光亮度平滑插值；无日出橙红（`getSunriseColor` 返回 null）。
  - **调试读数**：`/thetruthdebug cycle` 输出当前周期 tick、相位、blend、映射天空相位（人工验收工具，OP 2）。
- **验收结果（2026-09-26）**：✅ `build` 成功；✅ `runGameTestServer` `All 11 required tests passed`（新增 7 项：dimension JSON→自定义生成器 DFU 解码、三层 biome 注册、网格缺口签名（宽度/回绕/负坐标/观测台豁免）、层跨度带约束、相位边界、blend 单调性、天空映射逐 tick 连续与回绕）。三层均可达与观测周期观感（切换平滑、缺口笔直边缘）属游戏内人工验收，待用户 runClient 确认。
- **明确不在本批次（登记）**：「观测期缺口收窄 / 未观测期扩张」的**几何演化**未实现——已生成区块不会随 JSON/函数重算，几何演化需要方块操作或区块演化基建，推迟到 M3+（与确定性覆盖、方块变更基建一起评估）；本批次交付光/雾/天氛围层的周期差异。
- **过程收获（M2 核对的 1.21.1 硬事实，后续批次直接用）**：
  - 自写 ChunkGenerator 的写块契约（照抄 vanilla `NoiseBasedChunkGenerator#doFill`）：`chunk.getSection(chunk.getSectionIndex(y)).setBlockState(lx, y & 15, lz, state, false)` + `getOrCreateHeightmapUnprimed(OCEAN_FLOOR_WG / WORLD_SURFACE_WG).update(lx, y, lz, state)`——**必须手动维护两个 `*_WG` heightmap**，否则 SURFACE 状态的 heightmap 查询（如传送落点预筛）全空。
  - 自写生成器的 biome 填充：override `createBiomes(RandomState, Blender, StructureManager, ChunkAccess)`，调 `chunk.fillBiomesFromNoise(resolver, sampler)`；**resolver 收到的是 quart 坐标**（1 quart = 4 blocks，blockY = quartY << 2）。`StructureManager#registryAccess()` 可拿 registry。
  - `RandomState.create(HolderGetter.Provider, ...)` 的第一参数是 **`HolderGetter.Provider` 而非 `HolderLookup.Provider`**（`RegistryAccess` 不实现前者）；GameTest 里构造噪声用 `NormalNoise.create(RandomSource.create(seed), registryOrThrow(Registries.NOISE).get(key))`（与 M1 手法一致）。
  - 生成器按 `RandomState` 实例身份缓存地形形状（`getOrCreateNoise` 建噪声有置换表开销；RandomState 是 per-level 单例，双检锁保并行 fill 安全）。
  - **GameTest 的 `LEVEL_STEM` registry 同样不含 datapack 维度 JSON**（与 M1 FLAT preset 同根因）——generator codec 的验证改走 DFU：`LevelStem.CODEC.parse(access.createSerializationContext(JsonOps.INSTANCE), 打包在 mod 资源里的 JSON)`；`RegistryOps` 在 `net.minecraft.resources`。
  - 观测周期驱动：`ServerLevel#setDayTime` 只覆盖 dayTime 不动 gameTime；以 `gameTime % 周期` 为状态源每 tick 重写 dayTime 是无状态可重入方案。`LevelTickEvent.Post` 在 `net.neoforged.neoforge.event.tick`。
  - NeoForge 自定义维度效果：`RegisterDimensionSpecialEffectsEvent`（client mod bus）按 dimension_type 的 effects id 注册 `DimensionSpecialEffects`；订阅走主类构造器 `dist.isClient()` 守卫 + `modEventBus.addListener(EventClass.class, clientClass::method)`，避免 dedicated server 加载 `@OnlyIn(CLIENT)` 类（`EventBusSubscriber` 注解的 `bus` 属性已废弃，不用于 mod bus 事件）。

### M3 · 确定性覆盖与不稳定曲线（红线 2）

- **交付**：覆盖判定服务、玩家不确定度数据、三级曲线、预警表现（视觉噪点 / 闪烁 / 音效前摇）、「确界锚点」方块与其确定性场。
- **验收**：表层无损失；中层损失可恢复；深层有 3–5 秒预警且可挽救；**任何情况下无静默删除**；覆盖范围内不累积。

**M3 参数初值（全部为初值，调整不视为改设计）**：

| 参数 | 初值 | 理由 / 备注 |
| --- | --- | --- |
| 层判定边界 | 复用地形层：表层 y≥80 / 中层 -16≤y<80 / 深层 y<-16 | 与 M2 三层一致，单一来源（引用 `CertusTerrainShape` 常量） |
| 表层累积速率 | 0（不累积） | 文档 00 4.2："不累积或极慢……无实际损失"；视觉噪点按"未被覆盖且身处确界"即显示（教学） |
| 中层累积速率 | +1/秒（上限 100） | 中速；每 20 tick 结算一次 |
| 中层随机化阈值 / 恢复滞回 | 60 触发 / <50 恢复 | 超阈值：堆叠数量随机化并**记录原值**（物品 data component），覆盖后原值写回——零静默损失；仍超阈值时每 10 秒再随机一次 |
| 深层累积速率 | +5/秒 | 快速；20 秒从 0 到阈值 |
| 深层删除阈值 / 预警窗口 | 100 / 80 tick（4 s，落在 3–5 s 规范内） | 达到阈值不立即删除：剧烈闪烁 + 心跳音效 + actionbar 倒计时；窗口内进入覆盖 → 挽救（背包恢复、不确定度减半）；窗口结束仍未覆盖 → 清空背包（含装备）。非静默：有 24 秒总量前摇（20 s 累积 + 4 s 窗口） |
| 覆盖时衰减 | -4/秒 | 覆盖范围内**不累积**（速率归零）且快速回落；离开确界维度同衰减 |
| 确界锚点 | 覆盖半径 16 格；AE2 网络节点 idle 功耗 16 AE/t；场激活条件 = 节点 `isActive()`（在线且有电） | "需供能与维护"（文档 00 4.3）；不要求信道，M3 验收可用创造能源元件直连 |

**M4 设计决定（登记）**：
1. **空间 IO 基建「校验存在不消耗」**（2026-09-26 修订）：原设计「网络内含空间元件」经人工验收证实不可达——AE2 空间元件实现 `ISpatialStorageCell`（非 `IMEStorageCell`），只能放进空间 IO 端口，永不入网络存储。修订为「网络中存在空间 IO 端口 + 空间塔阵列合法（`isValidRegion()`）」：两者都是空间 IO 支线的稳定结构状态，完整复刻「做完空间 IO 支线」的门槛语义（红线 1 不变），且不要求元件常驻端口（元件是会被取放的活动物品）。

**M5 runClient 验收修复（2026-09-27，脐带锚点幽灵方块）**：
- **真凶（GameTest 关服日志抓到现行）**：`UmbilicalNetwork.unregister` 对 `pairId == null`（未绑定锚点）调 `ConcurrentHashMap.get(null)` 抛 NPE——**vanilla 的方块移除与 chunk 卸载路径都会调 BE 的 `setRemoved()`**，NPE 在 `LevelChunk` 的移除流程中途炸出：服务端 block state 残留 + BE 已移除 + 节点已销毁 = 用户观察到的"幽灵方块（线缆不连、更新后复原、无法再破坏）"。GameTest 32 项全绿掩盖了它（异常只在日志、不计入测试结果）——**验收纪律：GameTest 全绿仍须扫 runGameTestServer 日志异常**。
- **次生 bug（代码审查实锤）**：`releaseTicket()` 释放目标取自 `peerOf(this)`，对端先破坏注销后 `peerOf == null`，本端已发出的 FORCED 票**无法释放** → 对端 chunk 永久 ENTITY_TICKING 强加载。修复：票面目标记录在本端字段（`ticketDimension` + `ticketChunk`），释放按记录解引用（`server.getLevel(dimension)`），与注册表状态彻底解耦；`setRemoved` 先 `releaseTicket()` 再 `unregister`。
- **配套改进**：`UmbilicalNetwork.checkBind` 返回 `BindVerdict`（OK / PAIR_FULL / GLOBAL_LIMIT）区分拒绝原因，lang 拆为 `limit_pair`（该配对两维已满）与 `limit_global`（全存档 2 对已满）两条消息；`liveAnchors` 过滤已销毁残影；`register/unregister/peerOf` 全部 null 守卫。**语义澄清：单端 pair（只绑了一枚锚点）即占用全局对数额度**（绑定关系存在即一对）。
- 回归测试 `umbilicalFullPairReportsPairFullVerdict`（GameTest 33 项全绿）；异维度票泄漏路径无法在 GameTest 覆盖（M1 教训：GameTest 无法实例化 datapack 维度），修复正确性由代码论证 + runClient 复测。

原则：**把机制正确性尽量塞进自动化，只在游戏内验证观感与手感。**

| 手段 | 覆盖对象 | 说明 |
| --- | --- | --- |
| `./gradlew build` | 编译、数据生成、资源完整性 | 每批次必跑，CI 门禁 |

| 游戏内人工验证 | 维度观感、观测周期氛围、Boss 手感、入口仪式表现 | 无法自动化，逐批次人工确认 |

## 6. 交付与发布纪律

- **批次即推送**：每完成一个批次（实现 + 验证 + 提交）立即 `git push origin main`，不积压本地提交。
- **CI 门禁**：推送后用 `gh run watch <runId> --repo illagerCPR/the-truth --exit-status` 等 CI 变绿，再收尾汇报。
- **版本号单一来源**：版本号只写在 `gradle.properties` 一处；发布 checklist 必须包含"递增版本号"，并与 GitHub Release 在同一批次提交内完成。
- **发布前核对**：Release 前核对版本常量数值与目标 tag 一致，避免"界面一直显示旧版本"一类事故。
